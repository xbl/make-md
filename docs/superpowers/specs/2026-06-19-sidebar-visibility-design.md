# 侧边栏可见性行为设计

## 目标

改变侧边栏的默认可见性逻辑：App 启动时默认隐藏侧边栏（纯净编辑器），打开文件夹时自动显示文件树。类似 VS Code 的行为。

## 需求

1. **默认隐藏**：打开 App → 无侧边栏，纯净编辑器
2. **打开单个文件**：侧边栏保持隐藏（没有文件夹上下文）
3. **打开文件夹**：侧边栏自动显示，Files tab 展示文件树
4. **手动隐藏后打开新文件夹**：侧边栏重新显示
5. **不持久化文件夹路径**：重启 App 回到纯净编辑器状态

## 设计

### 核心原则

侧边栏可见性由「是否有打开的文件夹」驱动，同时保留手动切换能力。

### 行为表

| 场景 | 侧边栏行为 |
|---|---|
| App 启动 | 隐藏 |
| 打开单个 .md 文件 | 保持隐藏 |
| 打开文件夹 | 自动显示 |
| 手动隐藏后打开另一个文件夹 | 重新显示 |
| 手动隐藏后打开单个文件 | 保持隐藏 |
| 手动显示（Cmd+Shift+L）| 显示，可手动操作 |
| 专注模式（F8）| 强制隐藏，退出专注模式后恢复之前状态 |

### 实现方案

**改动约 3 个文件：**

1. **`src/stores/ui.ts`**：`sidebarCollapsed` 默认值从 `false` 改为 `true`
2. **`src/stores/folder-workspace.ts`**：`setRootPath()` 中调用 `useUiStore().sidebarCollapsed = false`
3. **相关测试**：更新 sidebar 可见性断言的默认值

### 不涉及

- 文件树功能（新建/删除/重命名/拖拽）已完整，无需改动
- 文件树图标（如有需要，单独评估）
- 文件夹路径持久化（明确不实现）
- 专注模式逻辑（保持不变）

## 测试要点

- App 启动后侧边栏不可见
- 打开文件夹后侧边栏可见，且 Files tab 显示文件树
- 打开文件夹后手动隐藏侧边栏，再打开另一个文件夹，侧边栏重新显示
- 打开单个文件不触发侧边栏显示
- 手动切换（Cmd+Shift+L）仍然正常工作
- 专注模式进出不影响侧边栏文件夹驱动的逻辑
